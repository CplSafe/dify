## Overview

P0 阶段把上游 [dreammis/social-auto-upload](https://github.com/dreammis/social-auto-upload) fork 到本地独立仓库 `/Users/guijinhao/Documents/social-auto-upload/`，**不嵌入 Dify**，通过 Docker 拆成 `sau-api`（FastAPI）+ `sau-worker`（Celery）两个进程，复用 Dify 的 Redis broker，建立 `sau_contracts` 共享 Python 包防止任务名漂移，建立 `SAU_INTERNAL_TOKEN` 内网共享密钥鉴权。本阶段**不实现任何业务路由细节**，只搭壳，验收点是 `curl /health` 通、`curl /accounts/{id}/check` 命中鉴权链路、Celery worker 能消费一条空 task。

## Requirements

- [REQ-1] sau 上游可 `git pull` 升级 — **禁止修改 sau 已有源文件**，仅 `add` 新文件；如果非改不可的（如 `pyproject.toml` 加依赖），列入 §B 的 "必须改清单" 并说明原因
- [REQ-2] sau-api 与 sau-worker 同 repo、不同进程、不同容器
- [REQ-3] 沿用上游 `uv` 包管理，沿用上游 `patchright`（Playwright fork，反检测）
- [REQ-4] 共享 Dify 现有 Redis（`redis://:difyai123456@redis:6379/1`，DB 选择见 §F）
- [REQ-5] `sau_contracts` 通过 `pip install -e` 同时装到 sau 与 Dify api（monorepo-friendly 软链接安装）
- [REQ-6] 所有 sau 路由（除 `/health`）必须经 `X-Sau-Token` 校验，token 来自 `SAU_INTERNAL_TOKEN` 环境变量
- [REQ-7] cookies 落到 `sau_data/cookies/tenant_{tenant_id}/{platform}/{sau_account_id}.json`，权限 0600，进程以非 root 运行
- [REQ-8] `/health` 端点不需鉴权，返回 `{"status":"ok","service":"sau-api"}`

## C. sau-api 拆分方案

### C.1 FastAPI app 结构

`apps/sau_api/main.py` 职责：
- 创建 `FastAPI(title="sau-api", version="0.1.0")`
- 注册全局依赖 `Depends(verify_sau_token)`（除 `/health` 外）
- 包含路由：`health`、`accounts`、`login_sse`、`publish`、`tasks`
- 启动时 log `SAU_INTERNAL_TOKEN` 是否就绪（不打印值），缺失 → 进程退出 1
- 通过 `uvicorn apps.sau_api.main:app --host 0.0.0.0 --port 8001` 启动

### C.2 原 `sau_backend.py` 路由处置

| 上游路由（Flask） | 处置 | sau-api 对应 |
|---|---|---|
| `POST /upload` | **弃** | 不复用，Dify 走 OSS 预签名 URL |
| `POST /login`（SSE） | **包** | `routers/login_sse.py` 调上游 SSE 函数；P0 阶段仅占位返回 501 |
| `GET /getValidAccounts` | **改** | 新接口 `POST /accounts/{sau_account_id}/check` — 单账号校验，返回 `{valid, checked_at}` |
| `POST /postVideo` | **包** | `routers/publish.py` — P0 仅做 `celery.send_task(PUBLISH_DOUYIN, ...)` 入队，返回 `{sau_task_id}` |
| `GET /getFiles` | **弃** | |
| `POST /deleteFile` | **弃** | |
| `POST /account/delete` | **包** | `routers/accounts.py::POST /accounts/{id}/delete`（P0 stub） |
| `GET /account` | **弃** | Dify 端有自己的 `social_publish_account` 表 |

**P0 范围内只真正实现两条路由**：
- `GET /health` — 实打实返回 `{"status":"ok","service":"sau-api"}`
- `POST /accounts/{id}/check` — 真实调用 sau 上游 `cookie_auth(account_file)`（见设计文档附录 A）

其余路由先打 `raise HTTPException(501, "not implemented in P0")` 占位，但鉴权、参数 schema、Pydantic 模型要齐全，方便 P1/P2 直接填实。

### C.3 关键依赖装配（伪结构）

```
verify_sau_token (FastAPI Depends)
  ├─→ 读 X-Sau-Token header
  └─→ 与 os.getenv("SAU_INTERNAL_TOKEN") 常量时间比较
       └─→ 不一致 → HTTPException 401
```

### C.4 cookie 文件路径解析

`accounts.py::check` 接收 `?tenant_id=xxx&platform=douyin`，解析路径：
```
sau_data/cookies/tenant_{tenant_id}/{platform}/{sau_account_id}.json
```
不存在 → 返回 `{"valid": false, "reason": "cookie_missing"}`，**不 raise 500**。

## D. sau-worker 拆分方案

### D.1 Celery app 配置（`apps/sau_worker/celery_app.py`）

- `Celery("sau", broker=os.getenv("SAU_BROKER_URL"), backend=os.getenv("SAU_RESULT_BACKEND"))`
- `task_serializer="json"`，`accept_content=["json"]`，`timezone="UTC"`，`enable_utc=True`
- `task_acks_late=True`、`task_reject_on_worker_lost=True`（设计文档 §5.4 强约束）
- `worker_prefetch_multiplier=1`（避免一个 worker 预取过多）
- `task_default_queue="publish_douyin"`（保守默认）

### D.2 Queue 注册

通过 `sau_contracts.queue_names` 导出三个常量：
```
PUBLISH_DOUYIN_QUEUE = "publish_douyin"
PUBLISH_XHS_QUEUE    = "publish_xhs"
PUBLISH_KS_QUEUE     = "publish_ks"
```

每个 task 文件用 `@app.task(name=PUBLISH_DOUYIN, queue=PUBLISH_DOUYIN_QUEUE, bind=True)`。

启动命令：
```
celery -A apps.sau_worker.celery_app worker \
  --queues=publish_douyin,publish_xhs,publish_ks \
  --pool=gevent --concurrency=4 --loglevel=info
```

### D.3 Playwright pool 策略（P0 仅占位）

`apps/sau_worker/pool.py` 设计骨架（P0 不实现，只画接口）：

| 决策 | P0 占位方案 |
|---|---|
| 是否复用 browser 实例 | **不复用**，每个 task 起一个 browser，task 结束 close — 简单稳，先求正确 |
| 浏览器位置 | `patchright install chromium` 装到容器镜像，路径 `/ms-playwright/`（见 §E） |
| 并发上限 | Celery `--concurrency=4`；`pool.py` 仅暴露 `async with browser_session() as browser:` 的 contextmanager 占位 |
| OOM 防护 | P0 不做，靠容器 mem limit + restart：unless-stopped |

`tasks/publish_douyin.py` P0 实现：
```

    # P0: 验证 payload schema, log "received", return {"status":"stub_ok"}

```

### D.4 Worker 健康暴露

`docker/entrypoint-worker.sh` 末尾：
```

```

## E. Dockerfile 设计

**文件**：`docker/Dockerfile`

### E.1 设计决策

| 项 | 决策 | 理由 |
|---|---|---|
| Base image | `python:3.11-slim` | 上游 `pyproject.toml` 要求 `>=3.11`；slim 精简 |
| 包管理 | `uv` | 沿用上游；先 `pip install uv`，再 `uv sync --frozen` |
| Playwright 浏览器 | 装到镜像层 `/ms-playwright/`，由 `PLAYWRIGHT_BROWSERS_PATH` 指向 | 镜像可复用，启动快；不从 host 挂载 |
| 多进程 | **单 Dockerfile** + 不同 entrypoint 脚本 + compose 不同 `command` | DRY，镜像复用 |
| 用户 | 创建 `sau:sau` UID 1000，进程不以 root 运行 | §I cookie 0600 安全 |
| Entrypoint | `entrypoint-api.sh` / `entrypoint-worker.sh` | 启动前 `scripts/ensure_cookie_dir.sh` |

### E.2 Dockerfile 结构（伪流程，不写真实 Dockerfile 内容到本计划）

```
1. FROM python:3.11-slim
2. ENV PYTHONUNBUFFERED=1 PLAYWRIGHT_BROWSERS_PATH=/ms-playwright UV_LINK_MODE=copy
3. RUN apt-get update && apt-get install -y --no-install-recommends \
       libnss3 libatk1.0-0 libatk-bridge2.0-0 libcups2 libxkbcommon0 \
       libxcomposite1 libxdamage1 libxrandr2 libgbm1 libpango-1.0-0 \
       libcairo2 libasound2 fonts-noto-cjk curl ca-certificates \
       (Playwright 必需的 X 库 + 中文字体；slim 默认不带)
4. RUN useradd -m -u 1000 sau
5. WORKDIR /app
6. RUN pip install --no-cache-dir uv
7. COPY --chown=sau:sau pyproject.toml uv.lock ./
8. COPY --chown=sau:sau packages/sau_contracts ./packages/sau_contracts
9. RUN uv sync --frozen --no-install-project              # 装依赖（含 sau_contracts editable）
10. RUN uv run patchright install chromium --with-deps   # 浏览器装到 /ms-playwright
11. COPY --chown=sau:sau . .
12. RUN chmod +x docker/entrypoint-api.sh docker/entrypoint-worker.sh \
        scripts/ensure_cookie_dir.sh
13. USER sau
14. EXPOSE 8001
15. ENTRYPOINT ["docker/entrypoint-api.sh"]               # compose 里 worker 服务用 command 覆盖
```

### E.3 entrypoint-api.sh 流程

```
1. 检查 SAU_INTERNAL_TOKEN 非空，否则 echo 报错 + exit 1
2. 检查 SAU_BROKER_URL 非空
3. ./scripts/ensure_cookie_dir.sh  (mkdir -p sau_data/cookies && chmod 0700)
4. exec uvicorn apps.sau_api.main:app --host 0.0.0.0 --port 8001 --workers 2
```

### E.4 entrypoint-worker.sh 流程

```
1. 同 1-3
2. exec celery -A apps.sau_worker.celery_app worker \
       --queues=publish_douyin,publish_xhs,publish_ks \
       --pool=gevent --concurrency=4 --loglevel=info
```

## F. docker-compose.yml 设计

**文件**：`docker/docker-compose.yml`

### F.1 网络方案：复用 Dify 默认 network

Dify 的 `docker/docker-compose.yaml` 没有显式命名 network，落地后默认 network 名为 `docker_default`（取决于 compose 项目目录名，通常是 `docker_default`）。

sau compose 顶层声明：
```yaml
networks:
  default:
    name: docker_default
    external: true
```

**前提**：Dify 必须先 `docker compose up -d` 起来，network 已存在。如果 Dify 的 network 名实际不是 `docker_default`（取决于用户的目录名/`COMPOSE_PROJECT_NAME`），**在 §J 验收前用 `docker network ls` 实查一次**，把 `name:` 改成实际值。

### F.2 services 结构（伪 yaml）

```yaml
services:
  sau-api:
    build:
      context: ..
      dockerfile: docker/Dockerfile
    image: sau:p0
    container_name: sau-api
    restart: unless-stopped
    ports:
      - "127.0.0.1:8001:8001"          # 仅本机暴露，外网不可达
    environment:
      SAU_INTERNAL_TOKEN: ${SAU_INTERNAL_TOKEN:?must set}
      SAU_BROKER_URL: ${SAU_BROKER_URL:-redis://:difyai123456@redis:6379/2}
      SAU_RESULT_BACKEND: ${SAU_RESULT_BACKEND:-redis://:difyai123456@redis:6379/3}
      SAU_LOG_LEVEL: ${SAU_LOG_LEVEL:-info}
      TZ: Asia/Shanghai
    volumes:
      - ../sau_data/cookies:/app/sau_data/cookies
    healthcheck:
      test: ["CMD", "curl", "-fsS", "http://127.0.0.1:8001/health"]
      interval: 15s
      timeout: 3s
      retries: 5
    depends_on: []                     # 不依赖 Dify redis，靠 healthcheck 等

  sau-worker:
    image: sau:p0                      # 复用 sau-api 构建出的镜像
    container_name: sau-worker
    restart: unless-stopped
    entrypoint: ["docker/entrypoint-worker.sh"]
    environment:
      SAU_INTERNAL_TOKEN: ${SAU_INTERNAL_TOKEN:?must set}
      SAU_BROKER_URL: ${SAU_BROKER_URL:-redis://:difyai123456@redis:6379/2}
      SAU_RESULT_BACKEND: ${SAU_RESULT_BACKEND:-redis://:difyai123456@redis:6379/3}
      TZ: Asia/Shanghai
    volumes:
      - ../sau_data/cookies:/app/sau_data/cookies
    depends_on:
      sau-api:
        condition: service_healthy
    healthcheck:
      test: ["CMD-SHELL", "celery -A apps.sau_worker.celery_app inspect ping -d celery@$$HOSTNAME || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 3

networks:
  default:
    name: docker_default
    external: true
```

### F.3 Redis DB 选择

Dify 已用 `redis/1` 跑自己的 Celery。sau 用：
- `redis/2` — sau Celery broker
- `redis/3` — sau Celery result backend

避免与 Dify 命名空间撞 key。

`docker/.env.example`（新增）：

## H. SAU_INTERNAL_TOKEN 鉴权中间件代码骨架

**文件**：`apps/sau_api/deps.py`（伪 Python，骨架级别）

```python
import os
import secrets
from fastapi import Header, HTTPException, status

_TOKEN_ENV = "SAU_INTERNAL_TOKEN"

def _load_token() -> str:
    token = os.getenv(_TOKEN_ENV, "")
    if not token or len(token) < 16:
        raise RuntimeError(
            f"{_TOKEN_ENV} must be set and >=16 chars at process start"
        )
    return token

_EXPECTED_TOKEN = _load_token()  # 进程启动即 fail-fast

async def verify_sau_token(
    x_sau_token: str | None = Header(default=None, alias="X-Sau-Token"),
) -> None:
    if x_sau_token is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="missing X-Sau-Token",
        )
    # 常量时间比较，防 timing attack
    if not secrets.compare_digest(x_sau_token, _EXPECTED_TOKEN):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="invalid X-Sau-Token",
        )
```

**应用方式**（`apps/sau_api/main.py`）：

```python
from fastapi import FastAPI, Depends
from .deps import verify_sau_token
from .routers import health, accounts, login_sse, publish, tasks

app = FastAPI(title="sau-api", version="0.1.0")

# /health 不挂 verify_sau_token
app.include_router(health.router, tags=["health"])

# 其余全部强制鉴权
protected = [accounts, login_sse, publish, tasks]
for r in protected:
    app.include_router(r.router, dependencies=[Depends(verify_sau_token)])
```

**安全要点**：
- token ≥ 16 字符（最好 32 hex），生成命令写到 `.env.example` 注释：`openssl rand -hex 32`
- 进程启动 fail-fast（导入 `deps.py` 即触发 `_load_token()`）
- 用 `secrets.compare_digest` 而非 `==`
- 错误响应不回显期望值
- token 不出现在任何 log（log 里只 log `len(x_sau_token)` 用于排查）

### I.3 写文件时强制权限

在 sau-api / sau-worker 中，凡是写 cookie 的代码（P1/P2 实现）必须：

```python
import os, json, tempfile

def write_cookie_atomic(path: str, data: dict) -> None:
    parent = os.path.dirname(path)
    os.makedirs(parent, mode=0o700, exist_ok=True)
    fd, tmp = tempfile.mkstemp(dir=parent, prefix=".tmp-", suffix=".json")
    try:
        with os.fdopen(fd, "w") as f:
            json.dump(data, f)
        os.chmod(tmp, 0o600)
        os.replace(tmp, path)        # atomic rename
    except Exception:
        if os.path.exists(tmp):
            os.unlink(tmp)
        raise
```

## Risks & Mitigations

| 风险 | 等级 | 缓解 |
|---|---|---|
